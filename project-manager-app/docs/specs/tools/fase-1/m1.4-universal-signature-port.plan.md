# Plan — Provider-neutral signature contracts with trusted control plane

**Spec:** `m1.4-universal-signature-port.spec.md` (`m1-4-universal-signature-port`)  
**Related:** #824  
**Status:** DRAFT — not a merge, deploy or production certification.

### Logical architecture
SEMSE Contracts and Policy/Approval → trusted tenant/connection context → `SignatureProviderRegistry` → approved provider adapter. Capability manifests say what provider *can* technically do, never what SEMSE *authorizes*.
### Implementation
1. Preserve common typed request with immutable PDF/version, signer roles, idempotency key, tenant and connection.
2. Separate request receipt from provider status, signed document evidence and downstream contractual execution.
3. Reject unknown IDs, duplicate providers, absent capability and untrusted connection IDs.
4. Introduce explicit optional operations (cancel, verifyWebhook, fetch artifact) only after actual adapter conformance.
5. Integrate with ADR-042 runtime and Settings → Integraciones; never introduce parallel policy engines.
### Compatibility
Existing Dropbox Sign remains available and historical contract records stay readable. No dynamic provider swap once an external envelope exists. A missing provider must fail rather than fall back to mock.
