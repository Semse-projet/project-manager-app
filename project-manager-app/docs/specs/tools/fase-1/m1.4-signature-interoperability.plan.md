# Plan — M1.4 Provider-neutral Electronic Signatures

**Scope:** umbrella spec `m1.4-signature-interoperability.spec.md`; governance slice specs are separately tracked against implementation PRs.

## Architecture
`SEMSE Contracts → canonical Policy/Approval → Universal Signature Port/Registry → tenant-approved Provider Connection → Documenso/Dropbox Sign/DocuSign → durable outbox/reconciler → evidence/verified PDF/certificate → Audit/Decision Ledger → conditional escrow eligibility`.

## Scope boundaries
- SEMSE is system-of-record; provider never authorizes business events.
- Prometeo drafts, recommends and monitors only within delegated scopes. No automatic sends or signing as humans.
- No silent fallback from a failing provider to another one after envelope creation.
- Do not treat provider `COMPLETED` or mock URLs as evidence of legal execution.
- Do not copy Documenso AGPL sources into SEMSE monorepo; evaluate exact upstream license before deployment.
- No production `prisma db push`, no destructive migration, no forced historical backfill.

## Test strategy
Unit and interface conformance → PostgreSQL uniqueness/locking and migration → staging real-provider contract send/poll/PDF validation → security abuse cases → Railway restore/rollback → authenticated canary.

## Approval / release
Separate code status, CI, merge, deploy, activation and verification. All candidate providers disabled by default until authorized operator enables **explicit tenant/connection allowlist**. Red flags (cross-tenant data, incorrect signer, bad hash, missing audit, duplicate sends) trigger disable-writes and quarantine.

## Traceability
Implementation PR #823/#824/#825/#826, security blocker #827. Each has distinct SDD 2.0 acceptance cases and must be reconciled with the umbrella spec; draft PRs alone do not prove delivered capability.
