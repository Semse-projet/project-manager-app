# Analyze — M1.4 Provider-neutral Signatures

## Trust and evidence model
Provider API connectivity **≠** sending authorization. Request receipt **≠** signature completion. Provider-reported completion **≠** verified contract execution. Verified execution and an escrow action are separate, policy-governed stages.

| Threat / fault | Mandatory control | Test/evidence required |
|---|---|---|
| Tenant A sees/signs B's contract | actor + contract/job + connection checks | cross-tenant and cross-connection 403; no network side effect |
| OPS_ADMIN/agent impersonates signer | canonical signer binding + informed consent | forged `signAs` denied |
| Human submits fabricated hash/url | signed PDF and certificate from verified provider | forged documentHash/pdfUrl cannot unlock escrow |
| Provider 401/timeout produces mock | fail-closed and explicit sandbox mode | fail/no `mock_sr_` and sanitized logs |
| Two requests for same intent | durable atomic reservation and fingerprint | real concurrent DB race and external idempotency |
| External POST succeeds but DB fails | checkpoint + reconciliation, no blind retry | injected crash at each stage; no duplicate |
| Fake/replayed webhook changes state | provider secret/sig, freshness, replay claim, separate Policy | forgery/replay blocked, polling confirms |
| Document amended after approval | immutable version/hash, approval scoped to version | rejection of mutated PDF |
| Bad provider switching on outage | sticky provider for active envelope | no unauthorized secondary send |
| Credential exfiltration/SSRF | fixed HTTPS origin, egress controls, secret references | redirect/URL/headers stress tests |
| Storage loss/rotated signing key | independent durable storage/keys, restore verification | recovery drill for signed artifact |
| AGPL or feature mismatch | version/license review with operator | explicit artifact + version approval |

## Observed vs proposed
- **Observed in reviewed PR descriptions/code:** Dropbox mode hardening (#823); neutral port (#824); Documenso adapter draft (#825); durable outbox draft (#826). These are not proofs of runtime integration.
- **Observed blocker:** legacy contract `sign` accepts caller-supplied documentHash and can mark signed without verifying a provider artifact (#827).
- **Proposed:** closed-loop signed evidence verification, consent, production provider choice, reconcilers, independent Railway deployment and compliance.

## Semantics and release invariant
An escrow-eligible state requires all: authenticated canonical signer identities; consent linked to unmodified version; provider confirmed completion via authenticated interaction; verifiable signed artifact and audit certificate; evidence hash and immutable custody; authorization decision in SEMSE; event committed atomically. Any missing element ⇒ blocked/manual review.
