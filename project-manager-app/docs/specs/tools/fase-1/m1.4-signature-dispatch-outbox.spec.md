# Durable Signature Dispatch Outbox and Recovery

> SDD 2.0 draft and evidence gate. Implementation/CI/deploy/activation statuses are not interchangeable, and these proposed requirements do not authorize sending live contracts.

## 1. Problema y resultado
External signature creation is not transactional with SEMSE's database: a timeout or crash can leave a successful envelope with no local receipt, and a retry could send multiple contracts. PR #826 adds an additive, durable signature dispatch journal. **Outcome:** at-most-one *attempt* per reserved key by default, durable checkpoints and an operator reconciliation path for uncertain outcomes. **No exactly-once guarantee is claimed.**

## 2. Alcance
**Included:** `SignatureDispatchOutbox` Prisma model and additive SQL migration; unique tenant/connection/provider/contract/key reservation; provider external ID uniqueness; request fingerprint, atomic transitions, ownership check before polling, duplicate denial.
**Excluded:** production scheduling, automatic reconciliation worker, outbox lifecycle disposal, backfill of old HelloSign requests, and live provider activation.

## 3. Actores, permisos y límites
| Actor | Scope / authority | Allowed | Forbidden |
|---|---|---|---|
| Authorized dispatcher | Trusted tenant+connection+contract+approval | reserve and checkpoint | mutate other tenant's request |
| Reconciler service | Explicit read capability + approval | inspect ambiguous provider outcome | blind retry/create again |
| Tenant admin | Audit/operations policy | investigate own requests | edit provider evidence manually to "completed" |
| Prometeo | Read-only delegated operational view | summarize blockers | write status or send without human authorization |

Outbox ownership is checked against canonical `Contract → Job.tenantId` before first provider effect. No external document contents, tokens, signer PII in logs.

## 4. Escenarios y aceptación
```gherkin
DADO dos envíos concurrentes para el mismo tenant, provider, connection, contract, idempotencyKey
CUANDO ambos intentan reservar
ENTONCES solo uno puede insertar la fila por constraint UNIQUE
Y el otro recibe conflicto sin invocar al proveedor
```
```gherkin
DADO que el proveedor creó un envelope pero la aplicación falló antes de persistirlo
CUANDO un operador intenta reintentar
ENTONCES el registro en estado RESERVED/ambiguo bloquea el reenvío
Y el proceso de reconciliación consulta el proveedor antes de cualquier nueva acción
```
- [ ] La misma key con fingerprint diferente es conflicto, nunca "last writer wins".
- [ ] CREATED no puede saltarse a SENT ni volver a RESERVED.
- [ ] Pertenencia de envelope exige tenant+connection+contract exactos; IDs ajenos = denegados.
- [ ] Crash/timeout de `create`, `created`, `distribute` y `sent` no genera duplicados.

## 5. Contratos
Internal `DocumensoOutbox.reserve(key)`, `.created(key+externalId)`, `.sent(key+externalId)`, `.assertOwned(context+externalId)`. Persisted status `RESERVED`, `CREATED`, `SENT` and future explicit `RECONCILIATION_REQUIRED`. Never treat SENT as a signed contract. Reserved keys include immutable document/signature payload fingerprint.

## 6. FSM, eventos y reconstrucción
Persisted checkpoints: `RESERVED → CREATED → SENT`; ambiguous failure requires a separate reconciliation record with correlation and immutable findings. A real recovery worker must only read a bounded tenant-scoped queue, enforce Policy and emergency stop, and require an explicit policy for external mutation after reconciliation. Audit/Decision Ledger lineage identifies provider response and operator decision.

## 7. Datos, migración y rollback
- **Model:** `SignatureDispatchOutbox`, unique `(tenantId, connectionId, providerId, contractId, idempotencyKey)`; second unique `(connectionId, providerId, externalRequestId)`; indexes for reconciliation.
- **Migration:** `20261008170000_signature_dispatch_outbox/migration.sql`, additive CREATE TABLE IF NOT EXISTS + indexes. No drops/backfill; do not edit after applied.
- **Verification:** `prisma migrate deploy` against fresh and previously migrated disposable Postgres, drift check, schema generated, uniqueness/ownership tested against real DB.
- **Rollback:** disable dispatch and leave journal intact; forward-fix DB schema rather than deleting audit history. No `db push` in production.
- **Retention:** document protected evidence lifecycle and storage governance before activation.

## 8. Observabilidad / despliegue
Counters: created, sent, duplicate denied, ambiguous, reconciliation age, unowned read attempt; alert on growing `RESERVED` queue. Logs use tenant/connection correlation only. Maintain independent feature OFF until authenticated test-run, operator approval and rollback runbook.

## 11. Riesgos y dependencias
Dependent on provider-neutral port #824, adapter #825, and canonical actor/Policy/Approval of ADR-042. The journal is not a substitute for vendor-side idempotence. Correlation does not guarantee server-side deduplication.
