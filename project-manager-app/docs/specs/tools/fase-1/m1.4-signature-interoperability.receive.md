# Receive — M1.4 Provider-neutral Signatures (2026-10-08)

## Requested outcome
SEMSE owns contracts, policy, signer identity/consent, Evidence/Audit/Decision Ledger, escrow eligibility and provider choice. A universal signature engine delegates execution to a self-hosted Documenso instance by default or to a **verified, tenant-approved** Dropbox Sign / DocuSign connection; existing Dropbox Sign is never destructively removed. Prometeo drafts and monitors but may not send or sign without explicit authority. This is an **architecture decision**, not a production deployment.

## Sources and known implementation
- Historical `m1.4-contracts.spec.md` remains unchanged; historical VERIFIED describes earlier scope only.
- PR #821 specifies new provider-neutral design (documentation).
- PR #823 targets silent HelloSign mocks, but keeps test_mode=1.
- PR #824 introduces port/registry, not provider integration.
- PR #825 introduces unregistered Documenso envelope adapter.
- PR #826 adds additive outbox in draft.
- Issue #827 identifies signing without provider-verified artifacts as a **release blocker**.

## Non-negotiables
Tenant/org/connection isolation, authority via canonical ADR-042 Policy/Approval, signer consent, stable PDF version, encrypted persistent storage, no invented signed evidence, no provider swaps after an envelope exists, replay/idempotency defense, emergency pause and auditable provenance.

## Decisions still to resolve
1. Documenso release image/digest, self-hosted feature availability, commercial license obligations, signing certificate/key custody.
2. Per-provider API/webhook capabilities and correct request/recipient identity mapping.
3. SEMSE authorized approval model and document version/consent evidence.
4. How to classify historical manual attestations versus provider verified signatures.
5. Railway storage topology, backup restore/RPO/RTO, privacy and legal retention.
6. Canary release/no-go authority, signed-artifact verifier and escrow gating.

**Explicitly not authorized here:** modifying production secrets, activating real sends or settling legal validity by status strings.
