# Plan — Close critical unsafe contract-signing/escrow evidence bypass

**Spec:** `m1.4-provider-verified-contract-execution.spec.md` (`m1-4-provider-verified-contract-execution`)  
**Related:** #827  
**Status:** DRAFT — not a merge, deploy or production certification.

### Trust boundary
Legacy `POST /v1/contracts/:contractId/sign` can accept client-supplied document hash/URL; repository state alone is not provider-verified signature evidence. Manual attestation and provider-verified signing must have distinct provenance and payment eligibility.
### Target flow
Immutable approved contract version → bound signer identities and explicit informed consent → provider executes → authenticated status/poll → signed PDF and audit certificate fetch → cryptographic validation, immutable hash and custody → Policy/Approval → atomic VERIFIED_EXECUTED event → conditional escrow eligibility.
### Security remediation
No generic OPS_ADMIN impersonation of either party. No arbitrary uploaded `pdfUrl` as evidence. Webhook must be authenticated and replay-protected but never grants business authority. Critical Audit failure must fail the transition, not be swallowed.
### Compatibility and rollout
Keep historical records readable as legacy/unknown verification, never retroactively upgrade. Code and migration work separated from this spec; block live provider-verified release until adversarial e2e and operator approval.
