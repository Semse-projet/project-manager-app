# Documenso V2 Envelope Signature Adapter

> SDD 2.0 — retroactive governance specification for an *in-progress draft* implementation. This artifact is not a production certification, nor an approval to send/sign contracts.

## 1. Problema y resultado
SEMSE needs self-hosted electronic signature execution while keeping contract governance and provider choice in SEMSE. PR #825 introduces a **non-registered** Documenso V2 envelope client. **Success:** a genuinely authorized request creates and distributes exactly one tracked envelope, and verified completion is never inferred from a network receipt.

## 2. Alcance
**Included:** pinned HTTPS instance URL, authenticated envelope API calls, PDF and signature-field inputs, external correlation, authorization gates before create and distribute, tenant/connection isolation, durable outbox obligation, explicit provider errors and status polling.
**Excluded:** live service registration, production webhook listener, signed artifact/certificate retrieval, final escrow verification, unattended retries, or signing on behalf of a user.

## 3. Actores, seguridad, responsabilidades
- SEMSE trusted control plane supplies tenant, connection, permissions, role, approved signer identities, policy decision and audit correlation.
- No provider API token or signing URL in Prometeo, browser logs or event payloads; token is server-side managed/rotatable.
- Recipient mapping must be matched to canonical contract parties and a signed version of the document, with explicit, attributable human consent before send.
- No unvalidated URL override; enforce fixed HTTPS origin and block SSRF/redirects. Network policy and DNS rebinding tests required prior to live.

## 4. Acceptance scenarios
```gherkin
DADO un contrato tenant-scoped con PDF válido, campos y aprobación vigente
CUANDO se envía mediante el adaptador Documenso
ENTONCES se reserva primero una clave durable de idempotencia
Y se registra el envelope draft antes de distribuirlo
Y una segunda aprobación/revalidación ocurre antes de distribuirlo
```
```gherkin
DADO que el proveedor devuelve error, un formato inesperado, o falla la persistencia
CUANDO la operación de envío queda incierta
ENTONCES no se intenta automáticamente crear otro envelope
Y la solicitud queda para reconciliación manual o autenticada
```
- [ ] Rechazar missing PDF, documentos truncados, posiciones fuera de rango, firmantes no autorizados, tenant/conexión equivocada.
- [ ] Comprobar idempotencia/doble envío bajo concurrencia real y crash entre create/distribute.
- [ ] Verificar versión API de la imagen autoalojada fijada, respuesta, fields, distribución, auth y rate limits con un test integrado.

## 5. Contratos
HTTP API de Documenso V2 `/api/v2/envelope/create`, `/api/v2/envelope/distribute`, `/api/v2/envelope/{id}` son **suposiciones de integración a certificar** en la versión escogida; no declarar compatibilidad de producción basándose solo en mocks. Status `COMPLETED` no implica `completedDocumentRef`; evidencia requiere artefacto firmado y verificado.

## 6. FSM / eventos / recuperación
`RESERVED → CREATED → SENT` (transport), seguido de `PENDING → PARTIAL → PROVIDER_COMPLETED → VERIFIED_SIGNED` (business). Una respuesta `COMPLETED` requiere polling autenticado, fetch de PDF final/certificado, hash SHA-256, cotejo de firmantes/versión, registro inmutable y Policy antes de efectos downstream. Webhook puede disparar consulta pero no es autoridad por sí mismo.

## 7. Persistencia / migración
No DB migration en #825; `SignatureDispatchOutbox` de #826 es prerequisito antes de activar. Prohibido auto-retry tras fallo ambiguo, incluso después de una excepción del proveedor.

## 8. Railway, observabilidad, rollout
Documenso se alojará como **servicio aislado** con Postgres propio, almacenamiento persistente/S3, certificado de firma, servicio de correo, backups verificados, health, secretos independientes, versión/digest fijo y rollback ensayado. Revisar licencia AGPL-3.0 y disponibilidad real de API/envelopes en modo self-hosted. Nunca afirmar LIVE si no hay prueba de firma en staging y canary autorizado.
