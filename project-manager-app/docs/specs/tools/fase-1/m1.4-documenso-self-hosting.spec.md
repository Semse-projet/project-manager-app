# Documenso Railway Self-Hosting and Recovery

> SDD 2.0 draft and evidence gate. Implementation/CI/deploy/activation statuses are not interchangeable, and these proposed requirements do not authorize sending live contracts.

## 1. Problema y resultado
SEMSE wishes to use Documenso as a default self-hosted *signature execution provider* while retaining portability to Dropbox Sign and DocuSign. Current PR #825 is an unregistered adapter and Documenso is **not deployed**. **Outcome:** a separately operated signing service with repeatable, secure deployment, recoverable storage and certified API/signing flow.

## 2. Alcance
**Included (proposed):** version/digest-pinned Documenso image, dedicated Railway app/service, isolated PostgreSQL instance, durable object storage for originals/sealed PDF, encryption/secrets, signing key/certificate, SMTP/background jobs, backup and restore, private networking where possible, monitoring and staging/canary.
**Excluded:** copying AGPL code into SEMSE monorepo, treating open source as unlimited licensing rights, automatic production sends, shared SEMSE Postgres credentials, unaudited upgrades.

## 3. Actores, permisos y trust boundary
- Infrastructure operator with limited Railway rights configures/rotates secrets; emergency pause for outbound signing.
- SEMSE service account has scoped API token; tenants never see this secret; one tenant's contracts cannot be enumerated by another.
- Prometeo may view safe health/status via SEMSE with permission but cannot access signing keys or rotate infrastructure credentials.
- Signed PDF and audit certificates are sensitive regulated records; encrypt in transit/at rest, explicit retention/backup policy and access audit.

## 4. Escenarios de aceptación
```gherkin
DADO un entorno staging con versión fijada y datos de prueba
CUANDO un usuario autorizado crea/firma un PDF
ENTONCES el certificado y PDF final se recuperan, verifican, hashean y archivan
Y un usuario de tenant ajeno no puede acceder a ellos
```
```gherkin
DADO pérdida del contenedor y reinicio en Railway
CUANDO se restaura una copia de seguridad representativa
ENTONCES se recuperan bases, archivos y claves indispensables
Y los IDs/envelopes siguen siendo reconciliables sin reenviar firmas
```
- [ ] Staging one full-cycle PDF/evidence smoke on the **pinned release**.
- [ ] Test webhook authenticity, replay and signed download permission, including revoked credentials.
- [ ] Confirm unsupported/enterprise-only API features are not relied upon.

## 5. Interfaces y contracts
SEMSE calls the fixed trusted HTTPS origin only; provider credentials server-only, enforced egress, no 302-follow to arbitrary URLs. Version-pinned `/api/v2/envelope/*` compatibility tested. No browser direct access to admin functions. Provider callbacks terminate at SEMSE verified ingress and are separately authorized for contract state transitions.

## 6. FSM y eventos
Provider is the signer execution subdomain, not SEMSE system-of-record. Outages enter `DEGRADED/PAUSED`, do not silently fall back to a different provider for an already created envelope. Recovery through outbox reconciliation; externally signed PDF is verified before downstream event emission.

## 7. Datos, backup, rollback y licencia
Separate PostgreSQL + persistent object store. Backup schedule, retention, restore drill and documented RPO/RTO approved **before** sending real contracts. Keys/secret rotation must retain access to previously signed documents. Pin image digest and record upstream changes/DB migrations. Rollback includes compatibility with prior schema: never downgrade database blindly. Review exact Documenso license (including AGPL/copyleft and enterprise feature terms) with legal counsel against planned commercial offering; document version and decision.

## 8. Railway readiness / operability
Health/readiness endpoints, outbound email telemetry, async job monitoring, DB/storage capacity and alarms, TLS and callback protection, rate limits, backup age and signing key expiry. Staging namespace and secrets isolated from prod. Provenance: image digest, build/run ID, migration version, evidence hash, approval actor, start/stop action. Canary first with explicit non-production signers; operations-only enablement after security/restore tests.

## 9. Required tests
- [ ] Image/API version matrix, licensing review, complete signing cycle with test PDF.
- [ ] PostgreSQL/S3 persistence and restore; key/cert rotation; stuck job/delivery retry.
- [ ] Tenant/auth boundary, SSRF/egress, forged webhook, partial signing/cancellation.
- [ ] Emergency pause, canary rollback, snapshot provenance and monitored SLO.

## 10. Implementación
Independent Railway service(s), **not** nested into the SEMSE API container. Adapter remains dormant until connected through trusted Integration Settings and canonical connector Policy/Approval. No Railway writes part of this specification.

## 11. Investigación externa
Source of truth must be Documenso release/tag for selected image, current hosting guide, license and API docs; test feature availability self-hosted rather than assuming hosted SaaS parity.
