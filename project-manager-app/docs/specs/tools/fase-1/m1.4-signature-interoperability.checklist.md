# Release Checklist — M1.4 Provider-neutral Signatures

> These checkboxes are deliberately NOT marked done merely because an author wrote code or a spec. Only evidence on the exact release SHA closes a gate.

## Specification / dependency
- [ ] M1.4 historical status preserved; new SDD 2.0 spec has truthful status and complete metadata.
- [ ] All slice specs (Dropbox fail-closed, signature port, Documenso adapter, outbox, verified execution, self-hosting) referenced and approved.
- [ ] Receive → requirements → threat → control → implementation → tests → evidence traceability complete.

## Trust, consent and data
- [ ] Tenant/org/connection/provider identity and canonical signer validation proven.
- [ ] Explicit human send approval, version-bound consent, no OPS_ADMIN/Prometeo impersonation.
- [ ] Provider tokens server-only; key rotation/revocation and redaction checked.
- [ ] Legacy self-attested sign endpoint cannot satisfy verified-execution/escrow gate.
- [ ] Signed PDF and certificate verified from provider; hash/lineage/audit atomically stored.
- [ ] Forged/replayed webhook, timeout, malformed API response, contradictory status fail closed.

## Recovery / operations
- [ ] No auto-retry on ambiguous external send and duplicate outbox reservation.
- [ ] Real PostgreSQL migration, uniqueness/race, reconciler and rollback tests.
- [ ] Dedicated Railway Postgres/object store/cert/email/job worker and staged pinned release.
- [ ] Backup **restore** tested, recovery objectives signed off, signing key lifecycle reviewed.
- [ ] License/terms and self-hosted API availability verified for exact version.

## Verification / go-live
- [ ] `pnpm spec:index` + `pnpm spec:validate:strict` passes exact SHA.
- [ ] Typecheck, build, unit, integration, security scan and e2e passed exact SHA.
- [ ] Signed test document, signer consent, callback, completed artifact, audit and reconciliation evidenced.
- [ ] Merge/deploy/provenance match; rollback drill and operator go/no-go recorded.
- [ ] Canary is deliberately enabled on allowlisted tenants; production Evidence and Audit confirmed.
- [ ] Only then update CI/deploy/activation/production_evidence and status VERIFIED.

**Stop conditions:** mismatched tenant, consent, document hash, unsigned payment transition, replay, missing certificate, provider redirect or inability to restore signed documents.
